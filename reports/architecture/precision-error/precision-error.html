The same trained parameters and inputs run through the network in each precision mode: none (float32, the reference), attention (bf16 attention cache and softmax-weighted values, float32 backbone) and backbone (bf16 backbone, the training default). A float64 backbone shows the reference's own floor. Errors are reported per block as relative token error and, at the output, in units of each source's posterior width. Can a bf16 token tell a 1σ move apart?

At the truth (t = 0.99, x̂ = x), each coordinate in turn is moved by one posterior width. The plot shows the change this makes to that source's float32 decode-input token, divided by the error from rounding that token to bf16. Below 1 (dotted), a backbone-mode network cannot see the move in its input.

What this means

  • Read the output in widths, not as relative error. A relative error of 10−3 in x̂1 does not matter at SNR 10, but it can be several posterior widths in f0 at SNR 1000. The second and third cards show which sources and coordinates cross 0.1 σ.
  • A late-t error moves samples further than an early one. The velocity is (x̂1 − x)/(1 − s), so at late t a fixed x̂1 error becomes a large velocity error. But the step toward x̂1 shrinks to match, so the end-to-end card is the number that decides.
  • The cached data stream is shared by every draw. An error in the data stream's keys and values shifts every draw from that observation the same way, which shows up as a bias rather than as extra width.
  • CPU numbers bound the casts, not the GPU's arithmetic. Training runs bf16 on GPU tensor cores. Rerun on a GPU for the numbers that describe a trained run's own sampler.
