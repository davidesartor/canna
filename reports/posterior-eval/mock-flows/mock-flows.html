Mock flows: stand-in posteriors with known defects

The lisa eval pipeline (eval, scorecard, validate) run on the same injections and keys as a real run, with the flow's sampler replaced by a mock. Each mock's eval dir has a real run's format, so eval pages can be checked against a known answer.

What is each mock?

Are the widths what the ladder says?

Median over the 128 eval injections' sources (one per log-uniform window, slots by f0) of the mock width over the Fisher forecast's width (draws.npz draws vs fisher, both sorted by f0, 1.4826 MAD in flow coordinates). fisher should read ~1 where the data dominate; the forecast and the mock differ in centre and in prior handling, so prior-dominated coordinates (quiet sources, fdot) need not. Columns: f0 per SNR band, then every coordinate over all sources.

Does the scorecard see it?

The scorecard's f0 columns over its eval + random injections (scorecard.npz), per true-SNR band: width over the monochromatic bound, 68% and 95% coverage. Calibrated: in68 ≈ 0.68, in95 ≈ 0.95.

Does SBC see it?

γ-test p-values of the truth's rank (scorecard.npz's validation scores), all slots pooled; red below 0.05. Marginal coordinates first, then data-dependent and joint quantities. The prior mock passes every marginal rank by construction (it is SBC's blind spot); the joint log-likelihood rank should catch it. Loud: the slots with snr_hat ≥ 100.
